# `reademe-temp` generated README static diagnostics

This run places deterministic static analysis beside the existing Linux
maintainer soft review of the README generated by the imported modular README
candidate.

The default feedback profile evaluated heading-level jumps, empty headings,
and images with empty alternative text. It emitted no diagnostics for this
README. The paired soft evaluator still recommended `request_changes` because
it found missing repository context/navigation and insufficient Linux guidance.
That difference is expected and useful: static analysis can identify properties
it was designed to measure, but a clean result is not evidence that the README
is semantically complete or mergeable.

[`run.json`](run.json) binds the analyzer configuration to the exact generated
README digest and records `automated_authority: evidence_only` and
`hypothesis_disposition: not_decided`.
