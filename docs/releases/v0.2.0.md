# `readme-review` / Codex adapter `v0.2.0`

Status: **experimental release**

This release completes the first evidence-to-capability-to-product factory
vertical. `readme-labs` owns the README domain model, canonical capability,
evaluation harness, generated Codex adapter, and repository Git marketplace.
The marketplace is the proper native installation channel for this release;
it is not a public or verified listing and does not become source authority.

## Evidence

The selected `v0.2.0-rc.1` blinded pair is preserved under
`evals/runs/v0.2.0-rc.1/`. The finding condition reported the deliberately
missing consumer path, while the adequate condition returned no material
findings and avoided all anti-findings. Both passed automatic gates and fresh
independent semantic review. The runner denied the executor access to the
factory checkout and network, read the scorecard only after executor exit, and
bound the result to the exact Git-object, marketplace, and installed-cache
product bytes.

The repository also preserves:

- independent review reports and their task identifiers;
- successful RC and final-product update, rollback, and restore sequences
  through native marketplace commands, with Git-object, marketplace, and
  installed-cache hashes checked at every state;
- failure dispositions for every material bootstrap/evaluation defect; and
- normal, unnamed-skill consumer reviews of immutable
  `repository-guidance@5b338322a4181e09e761429fbe158efa1fe7cf97`. The final-product
  run loaded plugin `0.2.0` from the native marketplace cache, produced one
  focused repository-specific finding, and did not edit the consumer.

The [factory runbook](../factory-runbook.md) is the reconstruction path.

## Install, update, and rollback

Resolve `v0.2.0` to its full 40-character commit, then use the native Git
marketplace flow:

```console
CODEX_HOME="$README_LABS_TEST_HOME" codex plugin marketplace add \
  https://github.com/k421o/readme-labs.git \
  --ref <v0.2.0-full-commit> \
  --sparse .agents/plugins \
  --sparse products/codex-plugin/readme-labs \
  --json
CODEX_HOME="$README_LABS_TEST_HOME" codex plugin add \
  readme-labs@readme-labs --json
CODEX_HOME="$README_LABS_TEST_HOME" codex plugin list --json
```

Update or rollback by removing the `readme-labs` marketplace, adding it again
at the target full revision, and reinstalling the plugin. The tested RC
predecessor is `0e845c375b3d16e90e3b93e45c32e6879ddc3b16`
(`0.2.0-dev.2`). Do not use the moving default branch. Do not use `v0.1.0` as a
drop-in rollback: it is an immutable historical compatibility artifact with a
different `readme-contract-review` interface.

## Compatibility and limitations

- Maturity remains experimental; interface version 1 is not a broad support
  promise.
- Evidence covers one controlled fixture pair, one model, and one run per
  condition. It does not establish general README-review efficacy.
- One no-finding run contains a disclosed count-based sandbox-denial
  correlation rather than exact machine attribution.
- Public/verified marketplace publication and registry rendering were not
  attempted and are not release criteria.
- `repository-guidance` still pins historical `readme-labs@v0.1.0`; the final
  `0.2.0` consumer run proves independent installation, normal discovery, and
  usefulness, not a completed downstream migration.
- Any Agent Skills integration is a future optional consumer boundary, tracked
  separately after this release.
